# 交付契约与阶段门禁

## 交付契约

完整功能开始前，在会话中维护一份简短契约；除非用户明确要求，不写入目标仓库。

| 项目 | 内容 |
| --- | --- |
| 业务目标 | 用户完成什么操作，系统产生什么结果 |
| 范围 | 包含和明确不包含的对象、PC 端、报表和环境 |
| 模型变化 | `BusinessObject`、`Model`、`Property`、`Index`、`RelatedBO` |
| 后端变化 | BO、规则、Logic、Repository、REST、配置、初始化和测试 |
| 前端变化 | `api`、`borep`、`bsapp`、`bsui/c`、注册和语言资源 |
| 报表变化 | RPT/RptToXml 输入、参数、SQL、字段、分组、布局和 JRXML 输出 |
| 数据库变化 | 表、字段、主键、索引、BO 元数据、SQL 和初始数据 |
| 验收条件 | 可观察、可判断通过或失败的业务或报表结果 |
| 环境条件 | 构建工具、数据库授权、服务、浏览器、Jasper 和外部依赖 |

推断内容要标记依据。对象类型、主子键、状态语义、目标数据库、报表输入和删除性操作不能仅凭命名猜测。用户明确确认的事实和本契约中已有的确认结果，可以作为下游阶段输入。

## 统一阶段结果

每个阶段按以下顺序交接：

| 字段 | 内容 |
| --- | --- |
| `status` | 阶段执行状态：`completed`、`partial`、`blocked` 或 `skipped` |
| 输入基线 | 实际使用的需求、XML、代码、JAR、Report IR 或环境标识 |
| 产出或修改文件 | 可定位的正式产物；临时产物单独标记 |
| 真实语义增量 | 模型、契约、行为、数据库或报表语义的变化 |
| 验证证据 | 静态检查、测试、构建、数据库核验或运行结果 |
| 未解决项 | 原因、所需条件和建议返回或进入的阶段 |

`completed` 只表示本阶段职责完成，不等于完整功能验收通过。必要环境未授权、不可用或必要证据缺失时使用 `partial`；输入不足且不能安全推进时使用 `blocked`；经范围判断不受影响时使用 `skipped`。非必要环境缺失只列为未运行项，不降低阶段状态。

最终验收阶段另给出 `verdict`：`passed`、`partially-passed` 或 `failed`。单条验收条件还可以是“不适用”；整体 `verdict` 不使用“不适用”。验收检查可以执行完成但得出 `failed`；不要用执行状态代替质量判定。

## 阶段交接要点

- 模型阶段交付最终 `Domain` XML、真实模型增量、推断依据和待确认语义。
- 代码生成阶段交付候选根目录、最小合并结果、跳过项、保留的手工代码和模板遗留项。
- Java 与 TypeScript 阶段分别交付稳定契约、实现、注册、资源、测试和构建结果。
- 报表阶段交付脱敏输入标识、JRXML、静态对照结果和无法验证的编译、数据或版式项。
- 数据库阶段交付命令模式、非敏感环境标识、实际输入、动作结果和后置核验。
- 验收阶段交付每项验收条件的证据、判定、未运行项和责任阶段。

## 门禁判定

| 门禁 | 进入条件 | 失败时返回 |
| --- | --- | --- |
| 模型确认 | XML 完整且关系、映射、类型明确 | 业务对象阶段 |
| 生成合并 | 候选有效且只合并真实模型增量 | 代码生成或模型阶段 |
| 后端契约 | 前端依赖的 App/Svc、REST 和序列化契约稳定 | Java 后端阶段 |
| 构建通过 | Java 与 TypeScript 受影响单元通过 | 对应开发阶段 |
| 报表静态检查 | JRXML 与 Report IR 一致且无敏感信息 | 报表迁移阶段 |
| 数据库授权 | 目标环境、配置和执行范围明确授权 | 保持 `partial`，不改变外部状态 |
| 最终验收 | 必要契约、运行时、数据库和行为证据完整 | 对应产物所属阶段 |
