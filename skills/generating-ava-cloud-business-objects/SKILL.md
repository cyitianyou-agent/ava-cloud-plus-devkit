# 生成 AVA Cloud+ 业务对象

## 概述

把中文业务描述转换为 AVA Cloud+ `datastructures` XML，或对已有 XML 执行最小化更新。用模型推断语义，用模板保证基础结构，并由大模型按清单逐项自检。

**执行前门禁：** 新建对象或新增模型需要模块简称。当前会话没有明确或已确认的模块简称时，只询问用户并立即停止；在得到简称前不检索项目、不分析现有对象、不建议简称、不选择固定模块目录。

## 开发流程位置

本 Skill 是完整功能交付中的业务建模阶段：

```text
delivering-ava-cloud-plus-feature
    ↓
generating-ava-cloud-business-objects（当前）
    ↓
generating-ava-cloud-code
    ↓
后端与前端开发 → 数据库落地 → 跨层验收
```

最终 `Domain` XML 是代码生成和数据库结构的共同模型基线。完成时必须交付最终 XML、真实模型增量和未确认语义；本 Skill 不生成代码、不连接数据库，也不把后续阶段未完成写成完整功能已交付。

## 核心原则

1. 按“用户本次要求 → 当前会话已确认信息 → 更新任务的目标 XML → 内置模板和规则 → 默认推断”的顺序取值。目标 XML 只用于更新定位和保留原值，不用于推断模块简称或输出位置。
2. 新建时从对应模板复制完整结构；不要凭记忆重写基础字段。
3. 更新时保留现有命名、映射、节点顺序、缩进、XML 声明和 `DOCTYPE`。
4. 能根据会话可靠判断对象类型、父子层级和输出位置时直接执行并说明；模块简称缺失或冲突时询问用户。
5. 完成前逐项执行结构与变更自检；发现问题时先修正，再重新从头检查。

## 准备资料

每次执行先读取 [business-rules.md](references/business-rules.md)。需要确认节点或枚举能力时读取 [xml-schema.md](references/xml-schema.md)。创建孙表或检查完整层级时读取 [complete-example.md](references/complete-example.md)。

新建时选择对应模板：

- 简单对象：`assets/templates/ds_ud_simple.xml`
- 主数据：`assets/templates/ds_ud_masterdata.xml`
- 单据：`assets/templates/ds_ud_document.xml`

Skill 已内置 XML 节点能力、正式类型组合、业务规则和三类最简模板。创建任务只使用当前会话与这些内置资料，不搜索项目中的业务对象、模块目录、源码或固定数据结构目录。

## 会话信息和输出位置

- 模块简称只采用当前会话中用户明确给出或已经确认的值。新建对象或新增模型需要模块简称而会话未提供时，先询问用户。
- 不从目录名、文件名、模块名称、目标 XML、`Domain.ShortName`、对象代码或其他项目文件反推模块简称。
- 输出位置优先采用当前会话明确给出的路径。会话已明确工作目标或交付目录且位置判断可靠时，自主选择其中合适的位置和文件名，并在结果中说明。
- 会话不足以可靠确定保存位置时，先询问用户；不搜索或默认使用 `src/main/resources/datastructures` 等固定目录。
- 更新任务只读取用户指定的目标 XML，不扫描其相邻文件或同模块对象。

按以下输入门禁执行，不跳步：

1. 判断任务是否新建对象或新增 `Model`。若是，检查当前会话是否已有明确模块简称。
2. 模块简称缺失或冲突时，只输出确认问题并结束当前轮次；不要调用文件搜索工具或给出候选简称。
3. 模块简称满足后，检查会话能否确定输出位置。能可靠判断就选择并说明；不能可靠判断就询问用户并结束当前轮次。
4. 两项满足后才读取内置资料并开始生成。更新既有字段且不新增模型时，不需要为了报告而从目标 XML 提取模块简称。

## 判断任务

- 用户要求创建、生成、新增对象：执行“新建流程”。
- 用户给出已有 XML 或要求增加字段、调整长度、增加子表：执行“更新流程”。
- 用户没有明确对象类型：根据语义推断；档案类优先 `MasterData`，业务单据优先 `Document`，配置或记录类优先 `Simple`。
- 新建或新增模型时会话没有模块简称：只询问用户并结束当前轮次，不先执行项目检索或给出候选简称。
- 用户没有给保存位置：根据会话中已经明确的工作目标自主判断；不能可靠判断时询问。

## 新建流程

1. 汇总当前会话中的业务描述、模块名称、模块简称和输出位置；缺少必需的模块简称或无法确定保存位置时先询问。
2. 根据会话语义确定对象类型、主表、子表和孙表层级。
3. 复制对应模板的 `Domain`、主模型、行模型和全部强制字段。
4. 生成文件名、`Model.Name`、`Model.Mapped` 和 `BusinessObject.ShortName`；新建统一使用 `AVA_AA_BBB`。
5. 按业务语义和内置规则追加字段，推断类型、子类型、长度、映射和枚举。
6. 为每个孙表在 `LineId` 后增加非主键 `ItemId`。
7. 递归建立 `RelatedBO Relation="OneToMany"`。
8. 只添加明确必要的唯一键和索引；不确定的索引只作为建议报告。
9. 先检查重复名称和映射，再写入根据会话确定的目标位置。
10. 按“结构自检”逐项核对，并直接阅读最终 XML 确认标签闭合、属性引号和层级缩进正确。

## 更新流程

1. 只读取用户在会话中指定的目标 XML，确认目标 `BusinessObject`、`Model` 和字段已经唯一定位。
2. 修改前读取并保留原文件内容，作为最小变更对照；如需副本，只放到临时目录，不要放进模块仓库。
3. 检查用户要求的字段是否已存在。已存在且符合要求时不重复新增。
4. 只执行用户要求的增加字段、明确属性变化、长度变化或新增层级。
5. 新字段放在语义相近字段附近；无法判断时放在最后一个 `Property` 后、首个 `Index` 前。
6. 新 `Model` 放在全部现有 `Model` 后、`BusinessObject` 前，并在正确父级增加 `RelatedBO`。
7. 不缩短现有长度，除非用户明确要求。
8. 对照用户要求逐项检查实际差异，确认没有删除、重命名、重排、批量格式化或无关属性变化。
9. 按“结构自检”检查全部新增内容；历史 XML 的既有不规范内容原样保留，不借机扩大修改范围。

## 结构自检

不要依赖 Python 或其他专用校验脚本。直接读取最终 XML，并按以下顺序自行检查：

1. XML 声明、`DOCTYPE`、开始标签、结束标签、属性引号和嵌套层级完整，根节点是 `Domain`。
2. `Domain` 下先放全部 `Model`，再放 `BusinessObject`；通常只有一个主业务对象。
3. 每个新 `Model` 已从对应模板完整复制强制字段、关键属性和相对顺序。
4. 主键、唯一键、孙表非主键 `ItemId` 与对象类型一致。
5. 每个 `BusinessObject.MappedModel` 和 `RelatedBO.MappedModel` 都指向已存在的 `Model.Name`，父子类型匹配。
6. 新建对象代码、表映射和层级编号符合命名规则且不超过长度限制；更新保留历史值。
7. 每个 `Model` 内的 `Property.Name`、`Property.Mapped` 唯一，索引只引用已存在字段。
8. 每个新增字段的数据类型、编辑类型、长度和枚举声明符合业务语义及正式组合。
9. 没有无依据的索引；找不到现有枚举时已记录待补全 `DeclaredType`。
10. 更新任务逐项对照原文件，确认实际变化只覆盖用户要求。

任何一项不确定时，重新读取内置模板和规则；仍无法可靠确定时再询问用户。

## 结果报告

完成后按以下顺序报告：

1. 创建或修改的文件路径，以及该位置来自会话明确指定还是模型根据会话自主判断。
2. 对象类型及推断依据。
3. 模块缩写、对象代码和表映射。
4. 新增或修改的模型、字段、长度、枚举和索引。
5. 所有推断值及其参考来源。
6. 新声明但尚未实现的 `DeclaredType`。
7. 自检结论，以及仍需用户确认或后续补全的事项。

## 快速自检

| 检查项 | 合格条件 |
|---|---|
| 模板字段 | 对应主表和行表字段一个不少 |
| 主数据行 | `Code + LineId` 联合主键 |
| 孙表 | 有非主键 `ItemId`，指向父级 `LineId` |
| 新建命名 | `AVA_AA_BBB`，对象代码不超过 30 位 |
| 更新命名 | 保留所有历史值 |
| 类型组合 | 符合正式映射；扩展值有明确提示 |
| 索引 | 只包含明确必要项 |
| 更新范围 | 没有删除、重命名、重排或无关变化 |
| XML 结构 | 标签闭合、属性引号、节点层级和引用关系完整 |

## 常见错误

- 把实例数据 XML 当成数据结构 XML：根节点必须是 `Domain`。
- 只写业务字段：必须先复制对应模板的全部强制字段。
- 把主数据行主键写成 `DocEntry + LineId`：应为 `Code + LineId`。
- 把孙表 `ItemId` 标成主键：`ItemId` 只记录父级子表的 `LineId`。
- 新建时照抄历史 `${Company}`：新建统一使用 `AVA`，更新才保留历史值。
- 为可能查询的每个字段建索引：只建立明确必要的少量索引。
- 扫描项目寻找模块简称或输出目录：模块简称只来自会话，输出位置只根据会话判断或询问用户。
