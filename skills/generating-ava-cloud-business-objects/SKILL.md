# 生成与校验 AVA Cloud+ 业务对象

## 目标与所有权

把业务语义落实为已确认的 `Domain` XML。本 Skill 唯一负责模型结构、映射、关系和真实模型增量；代码生成、Java、TypeScript 和数据库阶段只消费其结果，发现模型问题时应返回本阶段。

本 Skill 有三种模式：

| 模式 | 触发条件 | 正式结果 |
| --- | --- | --- |
| 创建 | 新建业务对象或模型 | 新的 `Domain` XML |
| 更新 | 用户指定已有 XML，并要求字段、层级、索引或属性变化 | 最小修改后的源 XML |
| 校验转换结果 | Excel 等工具生成了待确认 XML | 已确认的临时或指定 XML、修正清单 |

本 Skill 不生成代码、不连接数据库，也不把后续阶段写成已经完成。

## 输入门禁

创建对象、新增模型或修正 `Domain.ShortName` 时，模块简称必须来自以下已确认来源之一：

1. 用户当前明确给出或确认的值；
2. 当前任务上游交付契约中已经确认的值。

不得只凭目录名、文件名、错误的 `Domain.ShortName`、对象代码或未经确认的项目惯例猜测。缺少或冲突时只询问模块简称并停止会改变模型的操作。

输出位置优先使用用户指定路径，其次使用上游交付契约已经确认的目标 XML 或模块路径。两者都没有且无法可靠判断时询问用户。独立创建任务不得扫描项目来猜模块或输出目录；更新模式只读取用户指定或交付契约指向的目标 XML。

## 资料路由

每次执行先读取 [业务对象规则](references/business-rules.md)。只有需要确认节点、属性或枚举能力时读取 [XML 模型](references/xml-schema.md)；创建孙表或核对完整层级时读取 [完整层级示例](references/complete-example.md)。

创建时从对应模板复制完整结构：

- 简单对象：`assets/templates/ds_ud_simple.xml`
- 主数据：`assets/templates/ds_ud_masterdata.xml`
- 单据：`assets/templates/ds_ud_document.xml`

模板是新建对象强制字段、键和顺序的权威基线。主数据主表使用 `DocEntry` 主键、`Code` 唯一键；主数据行使用 `Code + LineId` 联合主键。

## 创建模式

1. 确认模块名称、简称、目标位置和对象类型。
2. 复制对应模板，确定主表、子表和孙表层级。
3. 新建对象代码统一使用 `AVA_AA_BBB`，并生成模型、表映射和文件名。
4. 按业务语义追加字段，确定类型、子类型、长度、映射和枚举。
5. 为孙表在 `LineId` 后加入非主键 `ItemId`，递归建立 `OneToMany`。
6. 只增加有明确业务依据的唯一键和索引。
7. 写入目标位置并执行最终结构检查。

## 更新模式

1. 唯一定位目标 `BusinessObject`、`Model` 和字段，以原文件为差异基线。
2. 只执行用户要求的新增字段、属性变化、长度变化、索引或层级变化。
3. 保留现有命名、映射、节点顺序、缩进、XML 声明、`DOCTYPE` 和历史例外。
4. 不缩短长度、不删除、不重命名、不重排或批量格式化，除非用户明确要求对应操作。
5. 对照原文件确认差异只覆盖本次需求，再执行最终结构检查。

## 校验转换结果模式

1. 把转换生成的 XML 当作候选模型，不因工具成功而视为已确认。
2. 根据已确认模块事实、业务描述、模板和规则检查 Domain、对象、模型、字段、键、映射和关系。
3. 确定属于转换器缺陷时，在临时汇总 XML 或用户明确指定的候选 XML 中做最小修正；默认不回写原 Excel，也不覆盖正式源 XML。
4. 无法从已确认输入决定的业务语义列为待确认项，不通过猜测让代码生成继续。
5. 输出已确认 XML、修正前后差异和仍待确认内容，再交给代码生成阶段。

## 最终结构检查

- XML 声明、现有 `DOCTYPE`、标签、属性引号、节点层级和根 `Domain` 完整。
- `Domain` 下先放全部 `Model`，再放 `BusinessObject`。
- 新建模型完整保留模板强制字段、键和相对顺序。
- `MappedModel` 全部指向存在的 `Model.Name`，父子类型匹配。
- 同一模型内 `Property.Name` 和 `Mapped` 唯一，索引只引用存在字段。
- 孙表有非主键 `ItemId`，主键与其模型类型一致。
- 新增字段类型、长度、枚举和映射有业务依据。
- 更新和校验模式的实际差异没有无关变化。

发现确定问题时先修正再从头检查；仍无法可靠确定时停止对应修改并询问用户。

## 阶段结果

按以下顺序报告：

1. `status`：`completed`、`partial`、`blocked` 或 `skipped`；
2. 输入基线和信息来源；
3. 最终 XML 路径，注明正式源文件或临时候选；
4. 真实模型增量及所有修正；
5. 推断依据、待实现枚举和待确认语义；
6. 结构检查证据；
7. 建议进入代码生成、返回用户确认或停止的原因。
